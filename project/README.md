# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

## 1. Паспорт проекта

- **Название проекта:** Прогнозирование ежедневных продаж розничной сети по категориям товаров.
- **Автор:** Шевцов Андрей Олегович
- **Группа:** ИНБО-22-24
- **Контакт:** tg: @gnomik101

- **Краткое описание:**  
  Проект решает задачу прогнозирования количества продаж (`Units Sold`) для каждой категории товаров розничной сети на 7 дней вперёд.

  Используются синтетические данные о продажах, классические модели временных рядов (наивный, скользящее среднее, Ridge-регрессия) и нейронная сеть GRU.

  Результат – REST API на FastAPI, которое по идентификатору категории и историческим значениям возвращает недельный прогноз.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - `01_eda_baseline.ipynb` - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - `data.py` - модуль для работы с данными;
  - `features.py` - модуль для генерации признаков;
  - `models` - модуль с описанием самих моделей;
  - `train.py` - непосредственно обучение моделей;
  - `service.py` - запуск сервиса.
- `data/` – демонстрационные/учебные данные:
  - `retail_store_inventory.csv` - открытые, синтетические и обезличенные данные по продажам магазина.
- `configs/` – конфигурационные файлы:
  - `config.yaml` - настройка параметров проекта.
  - `.env.example` - настройка переменных окружения.
- `tests/` – тесты.
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

## 3. Требования и установка

**Примечание:** в зависимости от вашей ОС и способа установки Python команда может называться `python`, `python3` или `py`.

Сервис поднимается на 8000 порту: http://localhost:8000;

У сервиса всего два эндпоинта:
  - GET /health – проверка работоспособности 
  - POST /predict – прогноз на 7 дней для заданной категории

Протестировать работоспособность сервиса можно через Swagger UI по адресу http://localhost:8000/docs или же с помощью curl-команд имеющих следующий вид:
```bash
# Базовый health-check
curl -X 'GET' \
  'http://localhost:8000/health' \
  -H 'accept: application/json'

# Проверка работы предсказания
curl -X 'POST' \
  'http://localhost:8000/predict' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "category": "Groceries",
  "history": [3499, 2767, 2295, 2948, 2829, 2958, 3293, 3771, 2563, 3239, 4087, 2731, 2558, 2691, 2773, 1718, 2564, 1912, 1253, 2646, 3729, 2367, 2075, 2509, 2240, 3745, 2546, 2503, 2540, 2227]
}'
```

## 5. Данные

**Краткое описание используемых данных.**

- Источник: открытый синтетический датасет "retail-store-inventory-forecasting-dataset", доступный по ссылке `https://www.kaggle.com/datasets/anirudhchauhan/retail-store-inventory-forecasting-dataset`
- Формат: CSV с ежедневными записями о продажах и запасах.
- Целевая переменная: Units Sold (количество проданных единиц).
- Агрегация: продажи суммируются по Date и Category, образуя 5 временных рядов (731 день каждый).
- Файлы хранятся в ./data:
  - `./data/retail_store_inventory.csv` – исходный датасет;
  - `./data/processed/` - каталог с агрегированными по категориям датасетами.

Подробнее можно прочитать в `./data/data_description.md`.

## 8. Ограничения и дальнейшая работа

В текущей версии сервис использует **Ridge-регрессию** для всех категорий — эта модель показала наилучшее качество по средним MAE и RMSE на этапе экспериментов. Прогноз строится исключительно на истории продаж (лаги, скользящие статистики, календарные признаки) без учёта внешних факторов (промо-акции, погода, цены конкурентов).

В дальнейшем можно добавить:
- **Динамический выбор модели** — автоматически подгружать для каждой категории ту модель (Ridge или GRU), которая показала лучшую валидационную метрику; GRU уже обучена и сохранена, но пока не используется в сервисе.
- **Экзогенные признаки** (праздники, скидки, погода) для повышения точности в периоды аномального спроса.
- **Вероятностное прогнозирование** — оценка доверительных интервалов, а не только точечного прогноза.
- **Мониторинг дрейфа данных** и автоматическое переобучение моделей при снижении качества.
